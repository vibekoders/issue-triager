# triage-service

The Restate service with one workflow per triage strategy: `Heuristic`,
`SingleShot`, `Workflow`, `Agent`, `Ensemble` and `DraftVerify`. Each has a
`run` handler that takes a `TriageRequest` and returns a `TriageResponse`
(see `triage-core` and `schema/`).

## Running

```sh
docker compose up -d restate                     # ingress :8080, admin :9070
cargo run -p triage-service -- serve             # listens on :9080

# Register the service (again after changing handlers):
curl -X POST localhost:9070/deployments -H 'content-type: application/json' \
  -d '{"uri": "http://host.docker.internal:9080", "force": true}'

# Triage one issue; the key is {run_id}:{config_hash}:{case_digest}:{repeat}.
curl -X POST localhost:8080/SingleShot/dev:aa413933d122:abc:0/run \
  -H 'content-type: application/json' --data @request.json
```

`serve` is the default command. SIGINT or SIGTERM stops the server and flushes
the last spans to Logfire.

A workflow runs once per key: posting the same key again returns `409`, and
the stored result is read with `GET /restate/workflow/SingleShot/<key>/attach`.

## Environment

| Variable | Default | Purpose |
|---|---|---|
| `LISTEN_ADDR` | `0.0.0.0:9080` | Address of the Restate endpoint |
| `CORPUS_DIR` | `./data/corpus` | Where the agent tools find `<owner>__<name>.sqlite` |
| `OLLAMA_HOST` | `127.0.0.1:11434` | Ollama, for `ollama:` chat and decision models |
| `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `GEMINI_API_KEY`, `GROQ_API_KEY`, ... | | Hosted chat providers (`anthropic:`, `openai:`, ...) |
| `TYPESAFE_API_KEY` | | Jev decision models (`typesafe:jev-latest`) |
| `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_API_TOKEN` | | Workers AI chat and Clef decision models (`cloudflare:`) |
| `LOGFIRE_TOKEN` | | Sends traces to Logfire; without it there's console output only |
| `FAIL_ONCE_AFTER_RUNS` | unset | Debug knob: after N journaled calls of an invocation, the next one fails once (retryable), so the retried attempt replays N calls. For checking replay and logging live; never set it for eval runs |

Models are addressed as `provider:model`, split at the first `:`
(`ollama:qwen3:4b`). Any provider key `allama-providers` knows works: chat
through `anthropic`, `openai`, `openai-chat`, `gemini`, `ollama`, `groq`,
`openrouter`, `cloudflare` and the other OpenAI-compatible presets; decision
models through `ollama`, `typesafe`, `cloudflare`, `openrouter`, `litellm`
and `digitalocean`. On Ollama, thinking is turned off for every chat call.

Costs come from the price table in `triage-core`; a model missing from it
costs 0 and logs a warning.

## Layout

- `models.rs`: chat, structured-output and decision calls with their spans
  and usage, and `journal`, which runs a call inside `ctx.run`.
- `tools.rs`: the agent tools over the SQLite corpus, cut off at `repo.as_of`.
- `strategies/`: one module per workflow. `sig_tokens.rs` is generated by
  `scripts/mine_sig_keywords.py` (heuristic v2's mined SIG keywords).
- `telemetry.rs`, `trace.rs`: Logfire setup and trace-context plumbing, so the
  handler spans join the eval harness's trace (`traceparent`). telemetry.rs
  has its own replay-aware log filter: restate-sdk 0.12.1's drops every event
  after replay in a retried attempt.
- `examples/heuristic_dev.rs`: scores the heuristic offline on normalized
  dev-split records (`cargo run -p triage-service --example heuristic_dev --
  FILE.jsonl`).
